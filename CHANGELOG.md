## Format Guide

### Version Structure

- `[X.Y.Z] - YYYY-MM-DD` for releases
- `[Unreleased]` for changes not yet released

### Change Categories

- **Added** for new features
- **Changed** for changes in existing functionality
- **Deprecated** for soon-to-be removed features
- **Removed** for now removed features
- **Fixed** for any bug fixes
- **Security** for security fixes and vulnerabilities

### Example Entry

```markdown
## [1.1.0] - 2026-02-15

### Added
- New authentication provider support
- Database query optimization feature
- User profile customization options

### Changed
- Updated dependency versions
- Improved error messages for clarity

### Deprecated
- Old API endpoints (will be removed in v2.0.0)

### Removed
- Legacy configuration format support

### Fixed
- Fixed memory leak in connection pooling
- Resolved race condition in concurrent operations

### Security
- Patched XSS vulnerability in markdown parser
- Updated security headers for better protection
```

## How to Update

1. Update this file with new changes under the `[Unreleased]` section
2. Before releasing, rename `[Unreleased]` to `[X.Y.Z] - YYYY-MM-DD`
3. Create a new `[Unreleased]` section at the top
4. Commit and tag the release
